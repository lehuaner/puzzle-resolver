# 2026-10-21

## 拼图定位台（puzzle-map.html）

- 交付文件：`puzzle-map.html`（单文件，无外部依赖）、`start-lan-server.bat`（局域网服务启动脚本，端口 8848）
- 需求：1000 片拼图进度看板，25 行 × 40 列，001 左上 / 1000 右下，每 250 片一个大区 A-D；三态（灰=未拼、绿=已拼、绿闪=进行中）；长按进批量选点；搜索定位并闪烁；localStorage 持久化。
- 关键设计决策：
  - **编号列优先**（先向下数满 25 行再右移一列），这样 1000=40×25、每区 250 片恰好是 10 列 × 25 行的整齐长条，且同时满足 001 左上 / 1000 右下。设置里可切行优先。
  - 大区视图不保持原几何，而是**按编号顺序 + 自适应列数**重排（算法：遍历列数取 min(W/c, H/r) 最大值），横竖屏都能把格子放到最大（横屏 23×11 格 77px，竖屏 12×21 格 78px）。
  - 全局视图铺满可用区域、格子允许非正方（否则竖屏会浪费 2/3 高度）。
  - 状态切换规则：灰→绿、绿→灰（撤销）、进行中→绿；"进行中"只由批量操作设置。
- 踩过的坑（已修）：
  1. 拖动连选的 `dragging` 标志在 pointerup 丢失时不会复位 → 整片被连选；已在 pointerup 无条件复位 + pointermove 加 `buttons===0` 兜底。
  2. 长按进批量模式后 `dragging` 未置 true，导致"长按后继续滑动"不能连选。
  3. 长按阈值 520ms 太易误触，调到 620ms。
- 已验证（chrome-devtools 实测）：单击/撤销、长按批量、拖动连选、批量设状态、搜索（精确 / A123 / 范围 / 大区 / 行 / 列 / 状态筛选）、定位闪烁、改配置重建保留进度、localStorage 持久化、横竖屏布局。

## v2 改版（同日，用户追加 4 项需求）

1. **点尺寸固定 + 画布可拖拽**：cellSize 默认 56px（设置里 40/48/56/64/80），不再按屏幕自适应。board 用绝对定位 + `translate3d` 平移，`touch-action:none`。拖动阈值 7px 与长按/点击区分：立即移动=平移，按住 620ms=批量，轻点=切换状态。整个 board 只构建一次 DOM（1000 格），切视图只改 transform + clamp，不重建。
2. **小地图（minimap）**：canvas 220×按比例，底图缓存到离屏 canvas（状态变化才重绘），视窗框每帧叠加。四角定位 class，`placeMinimap()` 检测闪烁点矩形与四个候选角是否重叠，自动避让（实测 br→bl）。可点击/拖动跳转。
3. **搜索大区联动**：`openSearch` 时 fZone 跟随当前视图区；`setView` 时若搜索面板开着则同步 chips 并重算，关键词保留。**跨区定位不再切到大区视图，而是切回"全部"再平移**（否则会被大区边界 clamp 锁住看不到目标）。
4. **照片识别（新增"识别"按钮）**：
   - 照片是拼图**背面**，每块印 `D-801` 这种编号。实测确认：横向相邻差 25、纵向相邻差 1 → **正是列优先每列 25 块，数字即全局编号**，与系统坐标体系天然一致。照片从背面拍，col 增大 x 减小（pitchX 为负），两点标定自动吸收镜像。
   - 前景分割：灰度 + Otsu（实测阈值 133）+ 连通域（保留面积 >1.2% 且跨度足够的区域）→ 拼图区域提取非常干净，地板和反光都被排除。
   - 尝试过但**放弃**的方案：自适应局部阈值切缝隙（C=15 全连通，块没分开）、梯度投影 + 自相关找周期（拼图齿干扰，峰值间距 4/5/7px 混乱）。最终用**两点标定算 pitch**（对角两块，行列都不同），再用**圆形采样前景占比 >0.55** 判定该格有块。
   - 精度兜底：标定后可拖动 canvas 平移网格、方向键/缩放按钮微调 pitch（±1.2%/次），实时 recalcScan 重算。
   - 实测案例图：识别 347 块 / 可判定 700 格，与照片中拼图面积估算（661400/1844≈358 块）吻合，绿色网格与拼图轮廓（含锯齿边缘、中间空洞）完全对齐。
   - 只加不减：仅把识别到的块设为已拼，不动其它块，可一次撤销。
- 修过的坑：识别面板 canvas 高度为 0（`.scan-body` flex 高度依赖 canvas 又反过来决定 canvas → 死循环），给 `.scan-body` 固定 `height:min(74vh,660px)` 并加 drawScan 尺寸保护。
- 识别实现要点：`buildScanBase()` 缓存照片+蒙版到离屏 canvas，否则每次重绘要重建 1.5M 像素 ImageData 会卡死拖动。

## v3 连通片区（待定状态）

状态从 3 态扩到 5 态：`0未拼(灰) / 1已完成(绿) / 2进行中(绿闪) / 3待定片(黄 #e09b13) / 4孤片(浅黄 #f2d582)`。

- **核心模型**：只有连到「最大连通片区」的块才算完成。`components()` 在"存在集合"(1/3/4) 上做 4-邻接 BFS，按大小降序；`promoteConnected()` 把最大片区里的 3/4 升为 1，返回变化列表供撤销合并。
- **单向规则（关键）**：`promoteConnected` 只升级不降级 —— 与主片连上的待定自动转绿，但用户手动点的孤立绿点不会被系统改成黄色。降级只发生在两个明确的入口。
- **照片识别应用**：先把识别到的块全设为 1 → 重算分量 → 非最大分量的**本次新增点**设为 3（既有绿点不动）→ 再 promote（处理旧待定因新块接入而连通）。`previewPendingSet()` 用 `states.slice()` 备份/恢复来预演，识别面板能提前显示"其中待定"的数量，预览框也是黄色的。
- **找点**：`locate()` 里若目标点状态为 0 且 `hasPresentNeighbor()` 为假（上下左右都没有 1/3/4），自动设为 4 并 toast 提示，走 undo 栈可撤销。
- `buildAdj()` 在 buildBoard 时预建邻接表，避免每次 BFS 重算 idxToRC。
- 撤销记录用 `Map` 收集（同一格可能被改两次：先设1再降3），必须保留**最原始**状态，否则回放会出错 —— 早期用数组 push 会导致撤销后状态是 1 而不是 0。
- 实测：001-005 已完成 + 007/008 待定，点 006 后 006/007/008 全部转绿、待定数 2→0、撤销能完整还原；找 500（孤立）自动标浅黄、找 006（挨着已完成）不标记。
