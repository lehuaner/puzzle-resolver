## v25 · 引导摆放三改（5ef0b99）

用户反馈四点：窄屏浮条按钮压住左侧信息；单块能拼成整块的应优先整块放；闪烁要用图例「进行中」那套而不是淡黄；闪烁区域要按屏幕比例控制缩放。

- **窄屏浮条**（`@media max-width:600px`）：`body.guideon .guidebar` 由 flex 改 `grid`，`grid-template-areas:"pic main" "btns btns"` → 编号+步数第一行、位置信息第二行、三个按钮独占底行（高 42，`#gdSkip` 68 / `.okb` flex 1 / `.gd-x` 44）。根因是 flex 一行时 `.gd-main` 只剩 139px，步数徽标被「跳过」压掉半截。
- **信息行改全局**：`#gdInfo` 一律 `order:3;flex:1 1 100%`、`.gd-step` `order:2;flex:0 0 auto`——浮条最宽仅 560，塞一行时位置信息会被挤成「…」（桌面也一样）。
- **队列连片合并**：并查集按 `S.adj`（网格 4 邻）把目标块并成「连片」，`ids.length<=9` 才算一条（>9 退回 OCR 组/单块）；标签 `组N·M块` / `连片·M块`。排序 `att（贴已拼区）→ n 大优先 → 质心距离 → head（最小编号，空棋盘时＝从上到下从左到右）`。85891：48 条 → **34 条**（17 组 + 3 连片[9/7/2] + 16 单块）。
- **闪烁换色**：`gblink` 类＝`background:var(--green)` + `animation:breath`（与图例 `.dot.f` 一致），灭相退回块本来颜色；位置靠常驻 `.gcur::after` 绿描边。**`.cell.gcur` 必须 `overflow:visible`**——`.cell` 基础样式是 `overflow:hidden`，描边会被裁掉（这次踩到，截图里看不到圈）。周期 620ms。
- **按比例聚焦** `focusItem(ids)`：bbox（`S.step`/`S.cellSize` 算）长短边塞进 `min(W, visH)*0.42`，`scale` 夹在 **0.55~2.6**；`visH` = 扣掉底部浮条盖住的高度（`wrapRect.bottom - barRect.top`），居中到 **visH/2**，目标不会被浮条压住。实测 500 宽 7 块组 scale 0.55、bbox 128px 居中 (250,271)；单块 scale 2.6、cell 146px；375 宽组 158px 居中，三排按钮均不与文字重叠。
- 测试技巧：验浮条排版不必重跑识别——`document.body.classList.add('guideon')` + 塞假文本 + 给 `#gdPic` 画个黑块，直接量 rect 即可；`resize_page` 仍然不生效，要用 `emulate({viewport:"WxHxDPR,mobile,touch"})`（切 emulate 会重置页面状态，需重跑识别）。

## v26 · 找点/引导统一「聚焦 + 高亮」（9d3a9f7）

用户要三点：找点找到后的闪烁改成「进行中」色；找点的缩放与引导用同一套；引导缩放要保证**至少一块已完成区域在画面里**，否则用户不知道自己的相对位置。

- **新增 `beacon.js`**：目标高亮只有一个实现。`beaconShow(ids)` = 给每块挂 `.gcur`（常驻绿描边，`::after`，`.cell.gcur` 必须 `overflow:visible`）+ 每 620ms 切 `.gblink`（`background:var(--green)` + `animation:breath`，即图例「进行中」）。`beaconHide()` 收掉。同一时刻只有一组目标，谁调谁接管。找点用 `setTimeout(beaconHide,9000)` 自动收。
- **新增 `board.focusSet(list,opt)`**（找点 + 引导共用）：
  ① 基准 `s1 = clamp(min(W,visH)*0.42 / max(bw,bh), 0.55, 2.6)`；
  ② 找最近的一块**已完成(1)**，算"缩到刚好能把它装进来"的 `need`，`need<s1` 时 `s=max(0.3,need)`（0.3 是下限，再小数字就看不清）；
  ③ 0.3 还装不下（离得远）→ **让位平移**：目标朝反方向让出「到中点」的距离，但让位量按**屏幕像素**封顶（`(W/2-70)/s` 板坐标），保证目标自己不出画面；
  ④ `visH` 扣掉底部浮卡（`#guideBar`/`#locCard` 的实际 `getBoundingClientRect().top` vs wrap bottom，最多扣 55%），目标居中到 `visH/2`。
- **找点**：`locate()` 与定位卡点编号都改 `focusSet([i])`（以前只平移不缩放）；顺序改成**先 `showLocCard` 再聚焦**（要量定位卡盖住多少）；`.cell.found` / `foundPulse` 那套金色描边退役，小地图避让选择器改 `.cell.gcur`。引导侧删掉自带的 `focusItem/startBlink/stopBlink`。
- **实测（500×900 DPR2，85891 先把组9(7块)标为已完成）**：
  - 找点 900（离已拼区 21 列 / 15 行）→ `scale 0.3`，目标 (418,605)、7 块已完成全在 (29~82, 304~357) 可见 ✓；找点 359（就在已拼区里）→ `scale 2.6`（cell 146px）居中 (250,473)、7 块已完成全可见 ✓；1280 桌面单块 → 2.6、居中 (640,471) 精确落在可视区中心。
  - 引导 组17·11块（离已拼区很远）→ 0.3，11 块目标 + 7 块已完成同时可见；组13 之类近的仍按 42% 规则放大。
  - 高亮：`gcur/gblink` 采样 7/7 ↔ 7/0 交替（620ms），找点 9 秒后 `gcur` 归零。
- 坑：**缩放约束里的"距离"都是板坐标**，让位平移若直接按板坐标封顶（`W/2-70`）实际屏幕只挪 `×s`，几乎无效——必须除以 `s` 换算成屏幕像素的封顶值。
