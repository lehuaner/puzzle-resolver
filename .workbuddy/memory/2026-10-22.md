# 2026-10-22 拼图定位台

## v4：无边框拖拽 + 缩放（puzzle-map.html，74.6KB / 1830 行）

### 本次改动
- **无限画布**：`clampPan()` 改为空函数（不做任何边界钳制），任意方向拖都行；丢失内容用 `⤢` 适应屏幕或点小地图找回。
- **缩放**：`SCALE_MIN=0.18, SCALE_MAX=3.5`；`setScaleAt(px,py,ns)` 锚点缩放；`fitToScreen()`、`zoomCenter(f)`、`resetView()`（装得下就居中，装不下从左上角开始，恒 1:1）。
- **四种缩放入口**：右上 `.zoombar`（＋/－/⤢/百分比 #zVal）；滚轮 `Math.exp(-deltaY*0.0018)` 以光标为锚；双指 pinch（`pointers` Map + `startPinch/doPinch`，抬一指不出 bug）；键盘 `+/-/0` 和方向键平移。
- **视口持久化**：`LS_VIEW` 从纯字符串升级为 `{z,s,x,y}`（兼容旧字符串格式，boot 里分支解析）；`applyPan` 末尾 `scheduleViewSave()` 300ms 防抖写入；boot 恢复 scale/tx/ty → 拼图跨天回来接着看。
- **小地图**：视口矩形除以 scale 并钳制在画布内（`x0=Math.max(0.8,...)`，`x1-x0>2` 才画）；避让顺序 `["br","bl","tl"]`（右上被缩放条占了）；**`applyPan` 里补调 `placeMinimap()`** —— 之前只有 flashFound 时避让，拖走/缩放后闪烁点被小地图盖住不会让位，现在松手即让。
- **找点闪烁时长 4.2s → 9s**：放大找片需要更长时间看。

### 测试中发现并修复的回归
- **长按连选失效**：v3 修过一次的问题在加 pinch 时又丢了 —— `enterBatch(i)` 本身不置位 `dragging`，长按后继续滑只会选中第一块。修复：长按 timer 回调里 `enterBatch(i)` 之后加 `dragging=true; dragAdd=true;`。
- **教训：拖拽/批量/pinch 共用 pointer 事件流，每加一种手势都要重跑"长按→滑动连选"用例。**

## v5：修闪烁范围 + 孤片旁的点可设状态（80.4KB）

### 用户反馈与修复
1. **"找点闪烁的是整个范围而不是目标点"** —— 真因：`.cell` 是 `position:static`，`.cell.found::after{position:absolute;inset:0}` 的定位上下文是 `.board`，金框+光晕铺满整幅画布。
   修复：`.cell{position:relative}` + `.cell.found{overflow:visible;z-index:5}`（原 `overflow:hidden` 会裁掉外发光和 scale(1.12)）。
   验证手段：`getComputedStyle(cell,'::after').width` —— 修复后 = 单格布局宽(50~56px)，修复前 = 整幅 canvas 宽。
2. **"孤点旁边的点被找到了，请支持设置状态"**
   - locate 规则升级：`neighborKind(i)` 返回 {main,lone}；未拼块只要**不挨着主片区(1/3)** 就标孤片 4（含"只挨着孤片(4)"的情况），toast 区分"挨着孤片区"/"不挨着已拼区域"；挨着主片区则不动，交给用户。
   - 新增**定位卡 `#locCard`**（底部居中 540×60，body.locon 显示）：编号 + 大区行列 + 当前状态，4 个状态按钮（已拼/待定/进行中/未拼，当前状态高亮）+ ✕；点左侧编号区 = 重新居中并再闪一次。开批量/搜索/识别面板时自动收起；`afterChange()` 里统一 `renderLocCard()` 同步状态显示。

### 顺带修的连通性隐患
- 原 `promoteConnected()` 取"最大连通域"晋升：一片**全是孤片/待定的小岛**只要比主片区大就会被误判成主片区自动转绿。
  改为：**任何连通域内只要存在已完成(1)，域内 3/4 全部晋升为 1**（这才是"两片相连后转完成"的准确语义）。
- 新增 `mainComp(base)` / `compHasDone(c,base)` 给拍照流程用：基准必须是**应用前就已完成**的块集合，否则刚设成 1 的新块会自己"当选"主片区，导致新增区域永远不会被降为待定。`base` 为空（一块没拼过）时退化为"取最大域"。

### 实测（chrome-devtools，file://）
- ::after 宽度从整幅缩回单格；`.cell.found` 恒 1 个。
- 找点 001（孤立）→ 自动 4；找点 002/003（挨着主片区）→ 保持 0 只闪。
- 512/513 孤片小岛不会自己变绿；定位卡把 513 设已拼 → 512 跟着转 1；撤销两者都回 4。
- 004 桥接后待定的 005 转完成，待定计数归零。
- 定位卡按钮（已拼→待定→未拼）、✕ 关闭、9s 后闪烁停止 + 点编号重闪，全部通过。
- 控制台无 JS 错误（仍是那 8 条 a11y label 提示）。

## v7：主片区已存在时，点击孤点记「待定」而非「已完成」（93.4KB）

用户反馈："已经拼出最大区域了，还随手点了孤点，不该直接标绿，应该算待定。"

- `tapCell(i)` 改：prev 为 1/3/4 → 取消为 0；否则先判 `mainComp().length`（有没有已完成的块）
  - 有主片区且 `!tapsIntoMain(i)` → 记 **待定 3**，并 toast「NNN 离已拼区域还远 · 先记为待定」
  - 否则 → 已完成 1（第一块、或接得上主进度的块）
- 新增 `tapsIntoMain(i)`：任一邻居落在**含已完成块的连通域**里就算接得上（覆盖"通过待定块间接连到主片区"的情况，比只看 `mainComp()` 最大域更准）。
- `promoteConnected()` 只在 next===1 时才调（原来 next!==0 就调，会把刚记的待定块反向处理）。
- 明确意图的操作不套用此规则：批量「设为已拼」、定位卡「已拼」按钮仍直接标 1。

实测：种子块→1；远处 510→3 且 toast 正确；挨着待定孤点的 509→3；把 510 明确设已拼 → 509 转 1；之后 tap 508（挨着已完成的 509）→1；撤销回到 0；再点取消→0。done/pending 计数同步正确。

## v8：多设备实时同步（server.js + 图谱管理）—— 交付形态从"单文件"变成"前端+服务端"

### 交付物
- `server.js`（11.7KB，零 npm 依赖）：静态托管 + **手写 WebSocket**（RFC6455 握手、帧解析/编码、mask、分片、ping/pong）+ `puzzle-data.json` 落库。启动 `node server.js [端口]`，默认 8848，HTTP 与 WS 同端口。
- `start-lan-server.bat`：改为启动 node server.js 8848（原 python 静态服务作废）。
- `puzzle-map.html`（106KB）：左上角品牌区变成图谱入口（当前图名 + 连接状态点）。

### 协议（WS /ws，JSON 文本帧）
C→S：`list / create{name,cfg} / rename{id,name} / delete{id} / join{id} / patch{id,cells{i:state}} / replace{id,cfg,states}`
S→C：`list{boards} / snapshot{board,peers} / created / renamed / deleted / patch|replace(广播给同房间其他人，by=发送者id不回环) / peers{n} / error`
- **落库时机**：每次 patch/replace/rename/delete/建立后立即 `writeFileSync`（用户要求"新增即落库"），不 debounce；无变化（`applyPatch` 返回 0）时不写不广播。
- 重名自动加序号（`uniqueName`）；join 到已删除的图 → 服务端自动开一张新图；删掉当前图 → 客户端自动进下一张，删空则 join `"-"` 让服务端开新图。

### 前端同步层
- `dirty` Map 收集改动 → `afterChange()` → `flushChanges()` 发 patch；全量场景（设置保存/清空/导入）走 `pushFull()` 发 replace。改 states 的 6 个点都插了 `markChange`。
- 视口（缩放/平移）**不同步**（每人视角不同），按图 id 存 localStorage：`puzzleMap.v2.view.<id>`；进度/cfg 只走服务端。
- 离线降级：`file://` 打开或 WS 断开 → `localMode`，数据写 `puzzleMap.v2.data.local`，UI 显示"仅本机保存"；断线自动重连（指数退避，实测重启服务器后约 2s 恢复且数据完整）。
- 地址栏 `#b=<图id>` 便于把同一张图分享给另一台设备；进入顺序：hash > localStorage 记住的 > 第一张。

### 实测（两个真实页面模拟两设备）
- B 点击格子 → A 实时变绿；A 批量 3 块 → B 实时同步；A 点 3 块因远离主片区变待定(3) 也照常同步。
- 图谱：新建→自动进入；重命名（行内 input，回车保存/Esc 取消）→ 另一台左上角图名同步；删除当前图→自动切下一张；删到最后一张→自动开新图。
- 落库 JSON 含 name/cfg(含 order/origin)/states；断线显示"连接中…"，服务恢复后自动重连、状态与 peers 计数恢复。
- 修过的两个 bug：① `boardId` 被 local 占位值占用导致首次连上不 join（改用 `serverJoined` 标志）；② 删掉当前图后卡死在已删图（deleted 分支自动挑下一张）。

### 踩坑
- **不要 `taskkill //IM node.exe`**：会把 chrome-devtools MCP（也是 node）一起杀掉，MCP 会掉线且不自动恢复。杀服务要用 `netstat -ano | grep :端口` 拿 PID 再 `taskkill //PID`。
- 测试脚本里 dispatch 的 pointerId 若残留会让 `scanPtr.size>=2` 误进 pinch 分支，现象是"交互全失灵"，务必 reload 后再跑完整流程。

### 遗留小事
- 设置面板的 number input 无 label 关联（a11y 提示，功能无碍）。
- 拖拽过程中（pointermove 直写 transform）小地图不避让，松手才让位 —— 可接受。
- 测试后已 localStorage.clear()，交付干净初始状态。

## v10：识别支持拼放方向旋转 90°（commit e933122）

### 用户反馈
`public/85890.jpg` 识别有问题：约 14 片 B 区块散在深色木桌上，标定后网格整体错位、识别结果错误。

### 根因（五组邻接关系验证）
照片里拼放方向**相对编号框架旋转了 90°**（列轴竖直、行轴水平），而两点标定只有对角仿射（pitchX 管列、pitchY 管行），无法表达 x∝row、y∝col：
- B-363 正下方是 B-338（同行列相邻）✓ 裁剪图目视确认
- B-363 正右/正上方是空桌（B-362/B-388 未拼）✓
- B-262 正上方 B-287、正左方 B-263 ✓（x/y 坐标严格符合）
- 按旧模型解 363→262 得格距 31.75×609（荒谬）；旋转解释 145×155（方形 ✓）

### 修复（scan.js + index.html）
- `computeScan` 拆出 `solveScan(forceRot)`：同时解普通(列→x,行→y)与旋转(行→x,列→y)两种轴向，按**方形度** `|log(|px|/|py|)|` 择优（阈值 s1<s0*0.6 才选旋转，常规照片保持原朝向）；dc/dr 仍须都非 0。
- 新增 `scanCellXY(p)` / `scanXYCell(x,y)` 统一正反变换，drawScanGrid / recalcScan / scanHitIdx 全部改走 helper。
- 微调条新增「⟳ 转向」按钮：`solveScan(!scan.rot)` 手动换轴（自动判断歧义时兜底，如 |dc|≈|dr| 且位移≈45° 的本质二义情形）；失败时保留原状态（computeScan 包装层才清 result）。
- tip 显示「横向拼放」状态；帮助文案补充说明。

### 验证（chrome-devtools 真实 UI E2E）
- fetch+DataTransfer 塞 85890.jpg → 派发 pointerdown/up 点两锚点 → pickNum 填号 → pickOk：自动判 rot ✓、格距 145×155、识别 16 块/63 可判/0 待定。

## v10b：识别应用后主界面定位（commit 2658cf2）

### 用户需求
主界面在缩放状态时，应用识别结果应该像「找点」一样：把结果设为视觉中心并高亮边框（即使区域不规则）。

### 实现
- `board.js centerOnSet(list)`：任意块集合包络盒居中；装不下时只往外缩到刚好装下（`scale=min(当前, (W-48)/w, (H-48)/h)`，不放大），`(maxC-minC)*step+cellSize` 精确算包络。
- `search.js flashRegion(list,ms)`：区域内每块按"邻块是否同在集合"决定画哪几边（`.hl` + `.hb-t/r/b/l`），共边不画 → 不规则轮廓连成一条完整线；金色 var(--found) 3px + drop-shadow 柔光 + hlPulse 呼吸，9s 自动清除（与找点同语言）。
- `scan.js bApplyScan`：应用后 targets=变更块（orig keys），无变化回退为整个 scan.result；跨大区先 setView("all") 再 60ms 后定位（同找点）。
- CSS `.cell.hl::after` 用 border-width 0 + 各边 3px 实现"选边描边"；`filter:drop-shadow` 跟随边框形状（比 box-shadow 不漏内部）。

### E2E 实测（85890 全流程）
- 先滚轮缩到 3.5× 偏离 → 应用后自动变 `translate3d(-1300,-1322) scale(2.282)`，**区域中心 (380,425) 与视口中心 (380,425) 完全重合**；16 块高亮、外沿 22 条边（t5/r6/b5/l6，不规则形 ✓）；内部块（312/288/338）无边框、边界块只画暴露边（截图核对）。
- **坑：`classList.add("hl hb-t")` 含空格直接抛 SyntaxError**（DOMTokenList 不接受多 token 字符串）——flashRegion 首版因此整段失效且 hlCount=0，必须逐个 add（remove 的多参数 varargs 没问题）。
- 测试副作用清理：板子上 16 块测试数据用设置里的「清空本幅进度」还原；冻结高亮用 `setInterval` 每 80ms 补挂类压过 9s 定时器（截图窗口不够时用）。

## v10c：窄屏批量模式按钮条重排（commit 472ba40）

### 用户反馈
窄屏长按进入批量模式后，5 个按钮（设为已拼/标为待定/设为未拼/进行中/退出）挤在一块。

### 方案
- HTML：退出挪进信息行（`.brow` 包住 binfo+退出），4 个操作键留在 `.bbtns`。批量监听在 #batchbar 上用 closest 找按钮 → 挪位置安全。
- 桌面：`.batchbar .brow{display:contents}` 解包 + `order`（bbtns=1, exit=2）→ 视觉与旧版完全一致。
- 窄屏(≤900px)：batchbar 改 column 两行——上行「信息 + 退出(右)」，下行 `.bbtns` 改 `grid repeat(4,1fr)` 等宽铺满，44px 高。
- **坑：`.brow` 类名与「我的拼图」列表行共用（.brow .binfo 等规则），批量条的新 .brow 规则必须限定 `.batchbar .brow` 作用域，否则列表行全炸。**

### 实测
- 390 视口（实际 500，桌面 Chrome 窗口有最小宽度）：上行 退出 54×34 右上、下行 4 键等宽 114×44 铺满 ✓ 截图核对。

- 退出按钮新位置功能正常；选择/连选手势不受影响。
- 测试技巧：长按进批量的合成事件必须派发到**格子元素**上（处理器用 e.target.closest('.cell') 找格子，派发到 wrap 找不到）；第二次 pointerdown 前必须先 pointerup 释放第一根手指，否则 pointers.size≥2 误进 pinch。

## v11：OCR 印刷编号模板库建成（任务 #12 完成，commit 待查）

### 最终管线（_ocr_lib.py extract_glyph）
- **字形正立化判据（核心突破）**：组件墨迹（局部 Otsu*0.75 阈值像素）bbox 宽高比——h≥1.12w → 字身竖直；w≥1.12h → 字身水平。**彻底兼容横排/竖排/斜排/正立竖排**（#67 是正立竖排：字符不旋转仅排列斜 -77°，旧 ang 采样全错）。
- **组件掩膜屏蔽**：_gen_cands.py 导出每组件像素掩膜 hex（m 字段）；提取时把**本候选其余组件掩膜内像素置 bgv=235**（防邻字笔画侵入 AABB）。检测连通域可能把半暗阴影带连进 bbox——**PCA/主轴分析被阴影带拉偏，勿用**；掩膜也不能用于 PCA（同因）。
- 24×32 双线性 + 旋转域粗网格(56)投影紧 bbox + 5%/80% 分位色阶归一。
- **4 假设（F+/B+/R+/F-）语义随提取管线改变**：种子方向须在**新管线下重新肉眼核读**（渲染 4 假设验证条）。最终 SEED：85890 的 B 系=B+、#3/#11=F-（旧 F+ 错）、模糊照 #60/#61/#82=F+、#65=B+。
- **验证结论**：LOO 仅 62.5%/28.1%（单样本类 9/0/7 剔除自身后库空必然崩=数据稀疏非算法缺陷）；**全库自洽 100%（64/64）**——表示法与匹配正确，运行时用全量库无此问题。
- 迭代定向在 margin_min=150 下不收敛（变更 14/14/11）——跑满 4 轮即可，种子冻结保证基线。
- ocr-templates.js：15 类 × ≤8 样本 × 768 hex（24×32），90KB。'- ' 类字形是竖直条（dash 被字身正立化旋转，全库一致）。
- 工具链：_gen_cands.py（检测+掩膜导出）→ _build_atlas.py（种子+4假设迭代+LOO+JS 输出+验证条 _verify_*.png / _ns_*.png）。
